# Product Spec — 메디큐브톡 커뮤니티

구현 방식(Frontend · Backend · 기술)과 무관한 제품 요구사항.
원본: `ASSIGNMENT.md` §3–4, 디자인 `design/메디큐브톡.fig`.
요구사항 ID(`P-xx`)는 하위 spec과 tasks에서 참조한다.

---

## 1. 범위

| 포함 | 제외 |
| --- | --- |
| 게시글 목록 · 상세 · 작성 · 수정 · 삭제 | 로그인 · 회원가입 · 사용자 관리 |
| 좋아요 토글 | 댓글 수정 |
| 댓글 목록 · 작성 · 삭제 | 데스크톱 레이아웃 |
| 초기 데이터(시드) 조회 가능 상태로 제공 | 아바타 선택 규칙의 정확성 (채점 제외, 자유) |

화면은 **모바일 웹, 뷰포트 375px 기준**이다. 피그마 디자인을 최대한 반영하고,
디자인에 없거나 흐름이 불명확한 부분은 임의로 완성한다. (무엇으로 완성할지는 사용자가 정한다 — `CLAUDE.md` 규칙)

## 2. 사용자와 본인 여부

- **P-01** 로그인은 없다. 요청자는 요청에 담긴 사용자 식별값으로 정한다. 식별값이 없으면 `apr_tester`로 간주한다.
- **P-02** 게시글 · 댓글의 작성자가 요청자와 같으면 **본인 것**이다. (대소문자 구분, 정확히 일치)
- **P-03** 식별값이 두 경로로 들어왔는데 서로 다르면 요청을 거절한다. (세부 규칙: `backend/spec.md` B-01)

## 3. 게시글 목록

- **P-10** 게시글은 **최신순**으로 표시한다.
- **P-11** 시간은 **상대 시간**으로 표시한다. (예: `3분 전`, `2일 전`, 현재 시각 기준)
- **P-12** 목록은 **무한 스크롤**이다. 끝까지 내리면 다음 묶음을 이어서 불러온다. 한 번에 전부 불러오지 않는다.
- **P-13** 각 항목은 작성자 · 제목 · 내용 미리보기 · 좋아요 수 · 댓글 수 · 작성 시간을 보여준다.
- **P-14** 항목을 누르면 상세 화면으로 이동한다.
- **P-15** 오른쪽 아래 작성 버튼을 누르면 작성 화면으로 이동한다.

## 4. 게시글 상세

- **P-20** 제목 · 작성자 · 작성 시간 · 내용 · 좋아요 수 · 댓글 수를 보여준다.
- **P-21** **좋아요는 토글**이다. 누르면 숫자와 아이콘이 바뀐다. 좋아요 여부는 요청자 기준이다.
- **P-22** 같은 사용자가 같은 글의 좋아요를 거의 동시에 여러 번 눌러도 각 요청은 **하나씩 반영**된다.
  요청이 모두 성공하면 최종 상태는 그 횟수만큼 순서대로 토글한 결과와 같다 (첫 번째는 좋아요, 두 번째는 취소).
  좋아요 수와 좋아요 여부는 항상 일치하며, 한 사용자가 같은 글에 좋아요를 두 번 남길 수 없다.
- **P-23** **본인이 쓴 게시글**에만 메뉴(⋯)가 있다. 메뉴를 열면 **수정하기 · 삭제하기**를 고를 수 있다.
  - 수정하기: 작성 화면과 같은 화면이 **기존 제목 · 내용이 채워진 상태**로 열린다. 저장하면 바뀐 내용이 반영된다. 제약은 작성과 같다 (P-40~P-42).
  - 삭제하기: 확인 다이얼로그 → "예"를 누르면 삭제되고 **목록 화면으로 이동**한다.
- **P-24** 남의 게시글은 수정 · 삭제할 수 없다.
- **P-25** 게시글을 삭제해 목록 화면으로 이동하면 완료 토스트("게시글이 삭제되었습니다.")를 보여준다. (과제에 없는 추가, D11)

## 5. 댓글

- **P-30** 댓글은 **최신순**이다.
- **P-31** 상세 진입 시 댓글은 **최초 2개까지만** 표시한다.
  - 댓글이 3개 이상이면 **더보기** 버튼을 보여준다. 2개 이하면 버튼이 없다.
  - **더보기를 누른 뒤부터는 무한 스크롤**로 이어서 불러온다.
- **P-32** 댓글을 작성할 수 있다. 빈 값인 댓글은 등록할 수 없다.
- **P-33** **본인이 쓴 댓글만** 삭제할 수 있다. 확인 다이얼로그 → "예"를 누르면 목록에서 사라지고 상세 화면에 머문다.
- **P-34** 댓글은 수정할 수 없다.
- **P-35** 댓글이 없으면 빈 상태를 보여준다. (디자인에 빈 영역만 있어 문구는 임의로 정한다)
- **P-36** 댓글을 삭제하면 목록에서 사라지는 것과 함께 완료 토스트("댓글이 삭제되었습니다.")를 보여준다. (과제에 없는 추가, D9)

## 6. 작성 · 수정

- **P-40** **제목과 내용은 모두 필수**다. 하나라도 비어 있으면 저장할 수 없고, 완료 버튼은 비활성 상태다.
- **P-41** 공백 · 줄바꿈만 입력한 제목 · 내용 · 댓글은 **빈 값**으로 본다.
- **P-42** **제목은 최대 20자**다. 글자 수는 **유니코드 코드포인트** 기준으로 센다.
  앞뒤 공백을 제거한 뒤 센다. (조합 이모지는 2자 이상으로 셀 수 있다.)
- **P-43** 제목은 앞뒤 공백을 제거해 저장한다. 내용 · 댓글은 입력 그대로 저장한다.
- **P-44** 내용 · 댓글에는 길이 제한이 없다.
- **P-45** 작성이 완료되면 **목록 화면으로 이동**하고 **완료 토스트**("게시글이 등록되었습니다.")를 보여준다.
- **P-46** 작성 · 수정 중 입력한 내용이 있으면, 뒤로 가기 화살표로 나갈 때 확인을 받는다. (과제에 없는 추가, D8)
- **P-47** 제목 입력 중 현재 글자 수와 최대 글자 수(`N / 20`)를 보여준다. 20자에 닿으면 더 입력되지 않는 이유를 알 수 있게 강조한다. (과제에 없는 추가, D10)

## 7. 삭제 정책 (게시글 · 댓글 공통)

- **P-50** 삭제해도 데이터는 지우지 않는다. 삭제되었다는 표시만 남긴다.
- **P-51** 삭제된 게시글 · 댓글은 목록과 상세에 나오지 않고, 게시글의 댓글 수에도 포함되지 않는다.
- **P-52** **게시글이 삭제되면 그 글의 댓글도 삭제된 것으로 간주한다.** 해당 댓글은 조회 · 작성 · 삭제할 수 없다.
- **P-53** 삭제된 게시글에 대한 요청은 **"삭제된 게시글"임을 알 수 있게** 응답하고,
  처음부터 없던 게시글은 **"존재하지 않는 게시글"** 로 응답한다. 두 경우를 구분한다.

## 8. 초기 데이터

- **P-60** 애플리케이션이 기동되면 `seed/seed.json`의 데이터가 **조회 가능한 상태**여야 한다.
- **P-61** 시드의 `id`는 그대로 유지한다. 새로 작성되는 게시글 · 댓글의 id는 시드와 충돌하지 않는다.
- **P-62** 시드에서 삭제로 지정된 게시글 · 댓글(`deletedPostIds` · `deletedCommentIds`)은 저장하되, 삭제 정책(§7)에 따라 조회에서 제외한다.
- **P-63** 댓글 수는 시드에 없으므로 댓글에서 계산한다. 삭제된 댓글은 세지 않는다.
- **P-64** 시드에는 좋아요 기록이 없다. 모든 좋아요 여부는 처음에 `false`이고, 좋아요 수는 시드 값에서 시작한다.
- **P-65** 재기동해도 시드가 **중복 적재되지 않는다.**
